# Только инженеру внедрения
Actual root migrate.main читает migrations/002_sales_manager.sql и выполняет cur.execute(sql), затем печатает MIGRATION_002_SALES_MANAGER_OK. Его нельзя автоматически превратить в universal bootstrap. Hook до postgres_store.connect: plan = build_migration_plan(source_root, schema=actual_schema). При любом validation error не подключаться к БД. Выход PLANNED_NOT_AUTHORIZED всегда, required_preflight — декларативная очередь проверок инженеру, не доказательство их выполнения.
Проверить actual SHA, фундамент runtime_next.tasks и остальные исходные foundation objects независимо. raw SQL 002 жёстко адресует runtime_next; schema≠runtime_next отклоняется SCHEMA_UNSUPPORTED. У inbox/lease {{schema}} должно остаться в plan. Это не исполняемый SQL и не разрешение выполнить три cur.execute подряд.
Inbox применяет существующий apply_migration(connect_factory=...,schema=...) со своими validate_schema/Identifier/catalog checks. Lease store не предоставляет migration runner: безопасная композиция и отдельная допустимая schema — отдельная работа интегратора. Не выполнять naive replace, не импортировать test runner для production, не применять к runtime_next без проверки его валидатора.
Полная lineage/ledger, проверка совместимости foundation, транзакционность всех стадий, replay и F115 journal migration вне этой задачи. Candidate не меняет migrate.py и не исполняет SQL. Связка NOT_CONNECTED; DB/restart/e2e NOT_RUN. Rollback planner hook не отменяет уже применённый DDL; DDL здесь не применяется.
