# F1-31 — описание реализации

## Назначение

Функция build_migration_plan(root, *, schema="runtime_next")
составляет проверяемый план трёх существующих миграций.

Функция не выполняет SQL, не подключается к базе данных
и не подтверждает готовность базы к применению миграций.

Параметр root указывает на каталог с исходными миграциями.
В выданном пакете это каталог reference.

## Проверки

1. Schema проверяется раньше root и файловых операций.
   Допускается только обычная строка "runtime_next".
   Ошибка: SCHEMA_UNSUPPORTED.

2. Root должен быть обычной строкой или объектом pathlib.Path.
   Несуществующий root или файл вместо каталога:
   INVALID_ROOT.

3. Компоненты "..", символические ссылки и Windows junction
   отклоняются. Проверяются сам root, его родительские
   каталоги и пути миграций.
   Выход за пределы root запрещён.
   Ошибка: UNSAFE_PATH.

4. Все три миграции должны быть обычными файлами.
   Ошибка: MISSING_MIGRATION.

5. SHA-256 исходных байтов каждого файла сравнивается
   с фиксированным значением из контракта.
   Ошибка: HASH_MISMATCH.

Проверки безопасности всех путей и наличия всех файлов
предшествуют чтению содержимого SQL.

Частичный план не возвращается.

## Сохранение SQL

Файлы читаются как bytes, затем декодируются в UTF-8.
Переводы строк не нормализуются.
Placeholders, включая {{schema}}, не заменяются.
SQL не разбирается и не переписывается.

Исходные SQL-файлы не изменяются.

## Результат

Возвращается MigrationPlan — namedtuple с полями:

- status: PLANNED_NOT_AUTHORIZED;
- entries: tuple из трёх tuple
  (relative_path, sha256, raw_sql);
- required_preflight: tuple точных строк из CONTRACT.json.

Порядок entries:

1. migrations/002_sales_manager.sql
2. f1_07_inbox/migrations/001_inbox_events.sql
3. first_task_leases/migrations/001_task_leases.sql

Это порядок представления плана, а не доказательство
безопасности последовательного выполнения SQL.

## Границы интеграции

Required_preflight перечисляет ещё необходимые внешние
проверки, а не сообщает об их успешном выполнении.

Существование и совместимость foundation, включая
runtime_next.tasks и исходные created_at/status,
функция не проверяет.

Root migration runner выполняет только миграцию 002.
Пакет не создаёт отсутствующий foundation.

Inbox использует собственные проверки schema и композицию
Identifier в существующем migration runner.

У first_task_leases.store нет migration runner.
Его нельзя считать готовым исполнителем миграций.

Проверки структуры БД, lineage/replay, транзакционного
поведения и регрессии перед применением остаются
ответственностью инженера внедрения.

integration_status: NOT_CONNECTED
DB/e2e: NOT_RUN
SQL execution: NOT_RUN

## Проверки реализации

На Windows с Python 3.12 пользователь выполнил:

python -B -m unittest discover -s tests -v

Результат: 15 тестов, OK.

Состав: 6 публичных и 9 собственных тестов.

Собственные тесты дополнительно проверяют:

- приоритет проверки schema;
- поддержку строкового root;
- сохранность исходных файлов и байтов SQL;
- изменение каждой из трёх миграций;
- каталог вместо SQL-файла;
- символическую ссылку вместо root;
- ссылку на каталог миграций;
- отсутствие файловых операций при инициализации модуля
  в пределах операций, перехватываемых тестом;
- точную сигнатуру функции.

Журнал финальной проверки целостности и запуска тестов сохранён в return/test.log.
