# F1-31 — Дмитрий стажёр
Одна задача: детерминированный проверяемый план трёх существующих миграций без выполнения SQL.
1. Проверьте CHECK_PACKAGE.py. Прочитайте CONTRACT.json и точные reference SQL; root migrate.py запускает только 002. В 002 уже есть ALTER runtime_next.tasks: база с foundation должна существовать заранее. Пакет не создаёт отсутствующий фундамент.
2. Изучите f1_07_inbox/migrate.py: {{schema}} компонуется psycopg.sql.Identifier и проверяется структура. В first_task_leases/store.py migration runner отсутствует; не придумывайте его. Сохраните raw placeholders и SQL побайтно по hash.
3. Реализуйте build_migration_plan в единственном разрешённом src модуле. Никакого I/O при импорте. Перед чтением проверяйте schema строго по CONTRACT (только runtime_next, иначе SCHEMA_UNSUPPORTED), затем root и безопасность путей. Никакого foundation_ready флага. Существование и совместимость foundation функция не проверяет и не утверждает.
4. Используйте фиксированные три path/hash из CONTRACT, не caller manifest. Каждый файл проверьте на regular file, отсутствие symlink и выходов за root. Считайте bytes, сравните SHA256, затем декодируйте UTF-8 без newline normalization. SQL не разбирайте и не заменяйте.
5. Возвращайте MigrationPlan namedtuple(status, entries, required_preflight) со status=PLANNED_NOT_AUTHORIZED; entries содержит tuple из трёх immutable tuple в точном порядке sales → inbox → leases, только когда весь набор raw файлов проверен. required_preflight — tuple точных строк CONTRACT, декларация незавершённых внешних проверок; не результат DB проверки. При любой ошибке — ValueError с точным кодом, без partial plan. Это порядок представления, не доказательство безопасного применения в БД.
6. Проверьте повторяемость, точные bytes/hash/order, точную декларацию foundation prerequisites, чужую schema, изменённый/отсутствующий SQL, symlink, traversal, отсутствие executor и import I/O. Подготовьте docs/IMPLEMENTATION.md и возврат по RETURN_GUIDE.md.
Приёмка: protected PASS, публичные и собственные unittest GREEN. Планирование не означает DB migration installed; DB/e2e NOT_RUN, wiring NOT_CONNECTED.
